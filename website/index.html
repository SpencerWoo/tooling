02 / THE IDEA

Almost sent.
Then, together.

An HTTP/1.1 request with a declared body length is incomplete until every body byte arrives. Send everything except the last byte on each connection, wait for preparation, then send the tails in a tight loop.

That moves most connection setup and request transfer ahead of the moment you want to coordinate.

ONE REQUEST / TWO WRITES
POST /measure HTTP/1.1
Content-Length: 5
Connection: close

hello
Sent during preparation Withheld until release

“hello” is 5 bytes. The final “o” completes the body.

04 / THE IMPORTANT DISTINCTIONS

Close in time.
Not a worker guarantee.

≈

Completion vs. execution

The technique delays full-body completion. A server may route requests or begin streaming work before it receives the final byte. Use an endpoint whose relevant operation waits for the entire body.

↗

Timing vs. routing

A load balancer and the server’s concurrency model choose the backend, process, thread, or coroutine. Timing alone does not establish affinity. Log worker identity to check what actually happened.

≠

Local writes vs. arrivals

TCP scheduling, TLS records, proxy buffering, and application scheduling add variation. TCP_NODELAY disables Nagle’s buffering; it does not guarantee immediate delivery or a packet boundary.

And HTTP/2?

The single-packet technique multiplexes requests over one connection. This tool uses separate HTTP/1.1 connections; their final bytes cannot share a single TCP packet.

05 / FROM CONCEPT TO TERMINAL

Run the real
experiment.

Python 3.10+ is all you need. The demo starts an instrumented loopback server, stages eight requests, measures completion times, and shuts down.

No external service. No dependencies. Run these commands from the repository root.

TERMINAL 
# Run the instrumented local example
python3 last-byte-synchronization/demo.py

# Run the verification suite
python3 -m unittest discover \
  -s last-byte-synchronization -v
READ THE OUTPUT

release_span_ns measures the client’s release loop. server_complete_body_spread_ns measures the demo server’s earliest-to-latest body completion. Nanosecond units do not mean nanosecond accuracy.
