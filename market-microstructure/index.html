01 / ORDER BOOKS

Price gets you eligible.
Priority gets you filled.

A book stores resting buy and sell interest. A matching engine decides which eligible orders trade. Better prices come first in this model; at one price, compare arrival-time priority with proportional allocation.

Read the full chapter ↗

One order, several fills

A buy limit is the most you will pay. If its quantity exceeds the best ask, it can walk to the next price—but never above its limit. This lab uses an immediate-or-cancel buy, so any remainder cancels.

The same price is not the same position

Alice arrived before Bob at $101. FIFO favors Alice. Our proportional rule divides fills by size, with largest-remainder rounding. Real venues define their own allocation and priority rules.

    02 / OPTIONS MARKET MAKERS

    See the move.
    Update the quote.
    Beat the next event.

    “Faster order flow” can mean faster data, faster computation, a shorter order-entry path, or a broker routing relationship. These are different advantages. Being a market maker does not imply seeing everyone’s pending orders.

    Read the full chapter ↗

    The quote can go stale

    Our call has a $2.00 model value, a $2.05 ask, and delta 0.50. A $1 underlying increase moves its estimated value to $2.50. This freezes every other pricing input; it is a local approximation.

    Routing is not clairvoyance

    A firm may receive flow routed through a broker, or participate in an exchange price-improvement auction. Neither establishes universal advance knowledge. Venue rules still determine allocation and execution.

      03 / MEV & CRYPTO

      The transaction order
      changes the trade.

      An AMM exchanges against pool reserves. Every swap changes the state used by the next swap. MEV concerns value from choosing transaction inclusion and order; arbitrage, liquidation competition, and harmful sandwiching have different economic effects.

      Visibility, ordering, and defenses are separate

      Private submission can limit public-mempool exposure, with service-specific trust assumptions. A minimum output bounds acceptable execution but can cause rejection. Block construction chooses a transaction sequence; an early HTTP arrival does not guarantee that position.
